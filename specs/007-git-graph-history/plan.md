# Implementation Plan: Git Graph History

**Branch**: `[007-git-graph-history]` | **Date**: 2026-09-06 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `/specs/007-git-graph-history/spec.md`

## Summary

Extend the existing project repository model and History page with repository-wide Git graph data and a complete read-only DiffEditor. Preserve the supplied sequential lane algorithm while adapting public object identities to the project's string-based model. Render graph topology in the existing DataGrid and render selected file diffs with parsed rows, fixed line-number gutters, synchronized vertical scrolling, code-only horizontal scrolling, interactive scrollbars, and visible-row virtualization.

**Scale/Scope**: Local and remote branch roots, 100 returned tracks, arbitrary parents and active lanes, independent project pages

## Phase 0: Research Decisions

Detailed rationale is in [research.md](research.md). Resolved decisions:

1. Enumerate local and remote branches through gix, peel readable references to commits, and skip bad individual refs.
2. Use one multi-tip walk sorted newest-first by commit time and take 100 results.
3. Isolate the supplied previous-output-to-current-input lane transition as a pure sequential builder.
4. Use typed gix IDs only inside repository processing and string IDs in public project records.
5. Enrich `CommitSummary` instead of duplicating it with a parallel `Track` model.
6. Draw arbitrary lane paths in `ProjectPage` using GPUI canvas and a cycling deterministic palette.

## Phase 1: Design

### Domain Model

See [data-model.md](data-model.md) for records, invariants, relationships, and the lane state transition.

### Interface Contract

See [contracts/project-history.md](contracts/project-history.md). This is an internal application contract; no network or persisted protocol is added.

### Implementation Sequence

1. Add graph marker/edge records and enrich `CommitSummary`; update exports and fixtures.
2. Add a pure track builder accepting ordered commit descriptors, HEAD, and branch labels.
3. Replace HEAD-only traversal with bounded, time-sorted local-plus-remote multi-tip traversal.
4. Populate full metadata and translate all fatal repository failures into `RepositoryError`.
5. Replace the placeholder merge glyph with a graph cell driven by marker and edges.
6. Keep selected-file loading and zero-padded changed-file list layout as project-page integration boundaries; implement the reusable DiffEditor under feature 008.
7. Extract author and committer independently from gix, preserve both in commit summaries, expose committer identity in selected commit details, and render message content without a redundant label.
8. Harden shared project-page scrolling and add topology, repository, page, failure, structural, and performance coverage.
9. Add measured-bounds, window-captured resizing to the three History split boundaries with centered 8px hit areas; derive each new boundary from its start position plus mouse movement delta.

### Validation Strategy

- Pure fixtures assert exact lanes, colors, waiting IDs, endpoints, flags, and output ordering.
- Temporary repositories assert roots, de-duplication, ordering, labels, HEAD, metadata, limit, and errors.
- Page contracts preserve loading, empty, retry, virtualization, and project isolation.
- Structural tests prevent GPUI in domain records, Git types in DataGrid, and Git CLI usage.
- Quality gates: format check, strict workspace clippy, and full workspace tests.
